JavaScript refresher

Unit I, first half. About 40 minutes. Everything here is JavaScript you will type inside React components.

Block-scoped variables: let and constMust know

A block is any code inside { }. let and const only exist inside their block; var ignores blocks.

Keyword Scope Reassign Redeclare
var function or global, not block yes yes
let block yes no
const block no no 
{ let marks = 90 }
console.log(marks)        // ReferenceError: marks only exists inside the { }

if (true) { var v = 1 }
console.log(v)            // 1: var leaks out of the block

Your deck says "var is globally scoped". That is the outer case; "function or global, not block" is safe against either wording.

Trap

const stops you reassigning the variable, not changing what is inside it.

const list = [1, 2]
list.push(3)              // fine: [1, 2, 3]
list = []                 // TypeError: Assignment to constant variable.

Say it

"let and const are block-scoped and var isn't. const can't be reassigned, so in React I use const by default and let only when a value has to change."

Arrow functionsMust know

A shorter way to write a function. No braces means an implicit return.

function multiply(a, b) { return a * b }   // normal function
const multiply = (a, b) => a * b           // arrow, implicit return
const square = n => n * n                  // one parameter: brackets optional
const point = (x, y) => ({ x, y })         // returning an object: wrap it in ( )

From your deck: arrow functions are anonymous, have no this, arguments or super of their own, and can't be used with new, so they can't be constructors. In React you meet them in event handlers (onClick={() => setCount(count + 1)}) and inside .map((item) => ...).

Say it

"An arrow function is a compact function with an implicit return when there are no braces. It has no this of its own and can't be used as a constructor."

Say it

"map returns a new array by transforming every item. filter returns a new array of the items that pass a test. reduce boils an array down to one value. map is how React renders lists."

DestructuringMust know

Unpack values from arrays, or properties from objects, into variables.

const [a, b] = ['HTML', 'JS']                     // a = 'HTML', b = 'JS'
const [, , third] = ['HTML', 'JS', 'JAVA']        // skip items with commas: third = 'JAVA'
const { name, course } = { name: 'Asha', course: 'CSE' }
const { name: studentName } = student             // rename while unpacking
const { role = 'guest' } = user                   // default if the property is missing

function Card({ name, course }) { /* ... */ }     // destructuring in the parameter list

The last line is how every React component reads its props.

Say it

"Destructuring pulls values out of an array or object into variables in one line. In React it is how a component reads its props, like function Avatar({ src, alt })."

Spread and rest operatorsMust know

The same ... does two opposite jobs. Look at which side it is on: giving values out is spread; collecting values in is rest.

const arr = [2, 3]
const more = [...arr, 4]                 // spread: [2, 3, 4], a new array
const older = { ...user, age: 21 }       // spread: copy the object, override age
sum(...arr)                              // spread: passes 2 and 3 as separate arguments

function sum(...nums) { /* nums is an array */ }   // rest: collects all the arguments
const [first, ...others] = [1, 2, 3]     // rest: first = 1, others = [2, 3]

Spread is how you copy and update state without changing the original. See immutability.

Say it

"Spread expands an array or object into individual pieces. Rest does the opposite: it collects the leftover values into an array. Same three dots, opposite direction."

ES modulesMust know

Each file is a module with its own scope. You choose what to share with export and pull it in with import.

// math.js
export const add = (a, b) => a + b        // named export
export default function App() { }         // default export: one per file

// another file
import App from './App.jsx'               // default import: no braces, any name
import { add } from './math.js'           // named import: braces, exact name
import { add as plus } from './math.js'   // rename on import

In React you write one component per file with export default. Vite serves your modules to the browser natively, which is part of why it starts so fast.

Say it

"ES modules let me split code across files. A file can have many named exports and one default export. I import a default without braces and named exports with braces."

ImmutabilityMust know

Never change existing data in place. Build a new copy with the change in it.

// Wrong: changes the array React already holds
items.push(4)
setItems(items)

// Right: a new array
setItems([...items, 4])

// Update one item in a list
setUsers(users.map(u => u.id === 2 ? { ...u, active: true } : u))

// Remove one item
setItems(items.filter(i => i.id !== 3))

Why React cares: it decides whether state changed by comparing references (see referential equality), and copies keep changes predictable and easy to trace.

Say it

"Immutability means I don't modify data in place; I make a new array or object with the change. React compares state by reference, so a new copy is what tells it to re-render."

Shallow and deep copyingMust know

Three different things people mix up:

const user = { name: 'Asha', address: { city: 'Delhi' } }

const same    = user                  // not a copy: two names for one object
const shallow = { ...user }           // new top-level object; nested objects still shared
const deep    = structuredClone(user) // everything copied: fully independent

shallow.name = 'Ravi'                 // user.name is still 'Asha'
shallow.address.city = 'Pune'         // user.address.city is now 'Pune' (shared!)
deep.address.city = 'Goa'             // user is unaffected
New top level? Nested objects How
Assignment b = a no, same object same =
Shallow copy yes still shared { ...o }, [...a], a.slice(), Object.assign({}, o)
Deep copy yes copied too structuredClone(o), JSON.parse(JSON.stringify(o))

JSON.parse(JSON.stringify(x)) drops functions and undefined and turns dates into strings, so structuredClone is the safer choice.

Trap

A shallow copy is not "the same memory location". That is plain assignment. Say this correctly in the viva; it is a favourite.

Say it

"A shallow copy makes a new top-level object, but nested objects are still shared by reference. A deep copy duplicates everything, so changes never leak back. Spread is a shallow copy."

Referential equality and state comparisonMust know

Objects and arrays are compared by reference (where they live in memory), not by what is inside. Numbers and strings are compared by value.

[1] === [1]              // false: two different arrays
const a = [1]
const b = a
a === b                  // true: same array
Object.is(a, b)          // true: this is how React compares old and new state
1 === 1                  // true: primitives compare by value

So React decides "did this state change?" by asking whether the new value is a different reference.

const [items, setItems] = useState([1, 2])

items.push(3)
setItems(items)          // same reference: React sees no change, so no re-render

setItems([...items, 3])  // new reference: React re-renders

Say it

"React compares state by reference, not by contents. If I mutate an array and set the same array back, the reference is unchanged and React skips the re-render. Creating a new array fixes it."

Declarative UIMust know

React's core idea: describe what the UI should look like for a given state, and React works out how to update the DOM. Both examples are from your deck.

// Imperative (vanilla JS): you find nodes and change them, step by step
const btn = document.getElementById('btn')
let count = 0
btn.addEventListener('click', () => {
  count++
  document.getElementById('label').innerText = count
})
// Declarative (React): describe the UI for each state; React updates the DOM
function Counter() {
  const [count, setCount] = useState(0)
  const increment = () => setCount(count + 1)
  return <button onClick={increment}>{count}</button>
}

Say it

"Declarative means I describe what the UI should look like for the current state, and React figures out how to update the DOM. Imperative code makes me find each element and change it myself."

JSX syntax and expressionsMust know

const name = 'Priya'
const items = ['HTML', 'CSS', 'JS']

function Welcome() {
  return (
    <div className="card">
      <h1>Hello, {name}!</h1>
      <p>{items.length} topics ready</p>
      <ul>
        {items.map(i => <li key={i}>{i}</li>)}
      </ul>
    </div>
  )
}

The rules:

  1. One root element (or a fragment: <>...</>).
  2. Curly braces run JavaScript. Only expressions fit: variables, maths, function calls, ternaries, &&, .map(). Not statements such as if or for.
  3. camelCase attributes: className (not class), onClick, htmlFor.
  4. Close every tag: <br />, <img />, <input />.
  5. Component names start with a capital letter. <Card /> is your component; <card /> is treated as an HTML tag.
  6. Lists need a key: a stable, unique id so React can track each item.
  7. Inline style is an object: style={{ color: 'red' }}. Two pairs of braces: the outer runs JS, the inner is the object.
  8. Comments inside JSX: {/* like this */}.

JSX is not HTML. Babel compiles every tag into a React.createElement() call, which returns a plain JavaScript object describing a DOM node. React uses those objects to build the Virtual DOM.

// You write
const el = <button className="btn" onClick={go}>Click me</button>

// Babel produces
const el = React.createElement('button', { className: 'btn', onClick: go }, 'Click me')

Newer tooling

Current React setups compile JSX to jsx() calls from react/jsx-runtime instead of React.createElement. The idea is identical, and createElement is the answer your deck expects.

Trap

Your Activity1 exercise asks what happens when you leave a tag unclosed. JSX gives a compile error, because it is stricter than HTML: <br> is fine in HTML but must be <br /> in JSX.

Say it

"JSX is syntax that looks like HTML but is really JavaScript. Babel compiles each tag into a React.createElement call. It needs one root element, curly braces for expressions, camelCase attributes like className, and every tag closed."

Functional components and the render lifecycleMust know

A functional component is just a JavaScript function that returns JSX. It re-runs every time its state or props change.

  1. Mountfirst time on screen
  2. RenderReact calls your function to get JSX
  3. CommitReact applies the changes to the real DOM
  4. State or props changethe cycle repeats from Render
function Greeting({ user }) {
  const [hovered, setHovered] = useState(false)
  return (
    <h1 onMouseEnter={() => setHovered(true)}>
      Hello, {user}!
    </h1>
  )
}

State survives between renders because React remembers it. Ordinary local variables do not: they are recreated every time the function runs.

Say it

"A functional component is a function that returns JSX. React mounts it, renders it, and commits the result to the DOM. Whenever its state or props change, it renders again and the cycle repeats."

Virtual DOM and reconciliationMust know

React keeps a lightweight, in-memory copy of the UI, the Virtual DOM: a tree of plain JavaScript objects. On every update it compares the old tree with the new one and patches only what changed.

  1. Previous virtual DOMul with li 1, li 2, li 3
  2. New virtual DOMul with li 1, li 2, li 3 (changed)
  3. Real DOMonly li 3 is updated in the browser
  • Diffing compares the old and new virtual trees to find the differences.
  • Reconciliation is the whole process: diff the trees, work out the minimum set of real-DOM operations, then apply them. That avoids costly full re-renders.
  • Real DOM updates are the slow part. Comparing plain JavaScript objects is cheap.
  • Keys let React match list items between renders, so it updates or moves them instead of rebuilding them.
Virtual DOM Real DOM
What it is Lightweight in-memory copy (JS objects) The actual page structure in the browser
Cost to change Cheap Expensive
Who changes it React, on every render React, but only with the minimal patch

Say it

"The Virtual DOM is a lightweight in-memory copy of the UI. On each update React builds a new tree, diffs it against the old one, and patches only what changed in the real DOM. That diff-and-patch process is reconciliation."

useState in 60 secondsNice to have

Component design

Unit II, part 1. About 40 minutes. How to shape components that are reusable, composable and easy to reason about.

Functional components, revisitedMust know

Every reusable piece of UI starts as a function that accepts props and returns JSX.

function Avatar({ src, alt }) {
  return <img className="avatar" src={src} alt={alt} />
}
  • Props are read-only. A component never modifies its own props. Data flows one way, from parent to child.
  • Destructuring keeps it clean. function Avatar({ src, alt }) is the idiomatic way to read props.
  • One function, many renders. The same definition produces different output for every combination of props.

Props-driven reusabilityMust know

Well-designed props turn one component into many looks, without duplicating markup.

function Button({ label, variant, onClick }) {
  return (
    <button className={`btn btn-${variant}`} onClick={onClick}>
      {label}
    </button>
  )
}

<Button label="Save" variant="primary" />
<Button label="Cancel" variant="secondary" />
<Button label="Delete" variant="danger" />

Same JSX and same logic; only the prop values change.

Props State
Who owns it The parent passes it in The component itself
Can the component change it? No, read-only Yes, through the setter (useState)
Changing it Parent re-renders with new props Calling the setter re-renders

Trap: "props drilling"

Passing props from a parent to its child is just passing props. Props drilling is passing them through several intermediate components that don't use them, only to reach a deep child. (Your App.jsx comment uses the term for the first case; fix it.)

Say it

Lifting state upMust know

When two components need the same changing data, move that state up to their closest common parent. Data goes down as props; changes come back up through callback props.

function Parent() {
  const [value, setValue] = useState('')
  return (
    <>
      <Input value={value} onChange={setValue} />
      <Display value={value} />
    </>
  )
}

Steps to lift state: (1) find the closest common parent, (2) move the useState there, (3) pass the value down as a prop, (4) pass the setter (or a handler) down so the child can ask for changes.

In your practice code, App holds selectedStudent; StudentList calls onSelectStudent(student) when clicked; StudentDetails receives student and displays it.

Reusable UI styling patternsMust know

Long class strings get hard to manage, so extract the pattern.

function Button({ variant = 'primary' }) {
  const styles = {
    primary: 'bg-blue-600 text-white',
    secondary: 'bg-gray-200 text-gray-900',
  }
  return (
    <button className={`px-4 py-2 rounded-lg ${styles[variant]}`}>
      Click me
    </button>
  )
}
  • Extract, don't repeat. If three components share the same class string, that string belongs in a shared component (or a constant).
  • Centralise variant maps. Keep the style-per-variant object in one place so a design tweak needs one edit.
  • Merge classes safely. Utilities like clsx or classnames combine conditional classes cleanly.

Trap

Never build class names from pieces, like `bg-${color}-500`. Tailwind only sees complete class strings in your source, so that class is never generated. Write the full string ('bg-blue-500'), as the variant map does.

Semantic HTML practices in ReactMust know

Browsers and screen readers already understand semantic tags; using them correctly gives you accessibility for free.

{/* Avoid */}
<div onClick={submit}>Submit</div>
<div className="header">...</div>

{/* Prefer */}
<button onClick={submit}>Submit</button>
<header>...</header>
  • A <button> is focusable and keyboard-clickable by default. A <div> is not, unless you add tabIndex and key handlers yourself.
  • Landmark tags (header, nav, main, footer) let assistive tech and browsers jump around the page.
  • Pair <label htmlFor="email"> with <input id="email"> so screen readers announce the connection. In React it is htmlFor, not for.
  • One h1 per page, then h2 for sections, in order. Use ul and li for lists.
  • A button performs an action; an a (link) goes somewhere.

Say it

"Semantic HTML means using the element that matches the job: button for actions, nav, header, main and footer for structure, and label paired with input. It gives keyboard and screen-reader support for free."

When it goes wrongMust know

Symptom Usual cause Fix
Tailwind classes do nothing Template CSS left in index.css, or a typo (Tailwind ignores unknown classes silently) Make index.css one line; check spelling
Things won't centre flex, justify-* or items-* on the child instead of the parent Move them to the parent
Text centred but the box isn't text-center only aligns text Centre the box with mx-auto and a max-w-*
Border is black or missing In Tailwind 4 a bare border uses the text colour Write border border-slate-200
Overlay hides the content Overlay is on top of everything Give the content relative z-10
Absolute element jumps to a page corner Its parent isn't relative Add relative to the parent
Image stretched Fixed size without cropping Add object-cover
Fine on desktop, broken on phone Built with prefixes only Put phone styles unprefixed; add md: for larger
A colour class doesn't apply Class name built from pieces (bg-${c}-500) Write the full class string
Nothing shows at all Component not rendered in App.jsx, or not imported Check the import and the JSX

The debug ladder:

  1. Add border border-red-500 to the suspect element to see its real box.
  2. Press F12, pick the element, and read the Styles panel. A struck-through rule was overridden; a missing class is a typo.
  3. Press Ctrl+Shift+M to test phone widths.
  4. Check index.css is one line.

Spot the bugMust know

Each snippet has exactly one mistake.

1.

<div class="card">Hello</div>
What's wrong?

It should be className. JSX attributes use JavaScript property names, and class is reserved in JavaScript.

2.

{students.map((s) => <li>{s.name}</li>)}
What's wrong?

Missing key. Write <li key={s.id}>. React needs a stable, unique key to track each list item between renders.

3.

function add() {
  items.push('new')
  setItems(items)
}
What's wrong?

It mutates state and passes back the same array, so React sees the same reference and doesn't re-render. Use setItems([...items, 'new']).

4.

return (
  <div>
    {if (isAdmin) { <AdminPanel /> }}
  </div>
)
What's wrong?

if is a statement, and JSX braces only accept expressions. Use {isAdmin && <AdminPanel />} or a ternary.

5.

<div className={`bg-${color}-500 p-4`}>...</div>
What's wrong?

Tailwind only generates classes it can see as complete strings. Use a map: const bg = { red: 'bg-red-500', blue: 'bg-blue-500' } and className={`${bg[color]} p-4`}.

6.

<button onClick={handleDelete(id)}>Delete</button>
What's wrong?

handleDelete(id) runs during render, not on click. Pass a function instead: onClick={() => handleDelete(id)}.

7.

What's wrong?

Component names must start with a capital letter. <card /> is treated as an HTML tag. Rename it Card.

What's wrong?

When items is empty, 0 && ... evaluates to 0, and React renders the number 0. Use {items.length > 0 && <List items={items} />}.

A component must return one root element. Wrap both in a <div> or a fragment: <>...</>.

The 15 core questionsMust know

1. What is the difference between an SPA and an MPA?

In an MPA every navigation asks the server for a fresh HTML page and the browser reloads. In an SPA one HTML page loads once, and JavaScript swaps the views on the client, fetching data as JSON from APIs, so there is no reload. React apps are SPAs by default. The trade-off is extra work for SEO and routing.

2. What does "declarative UI" mean?

I describe what the UI should look like for a given state, and React works out how to update the DOM. Imperative code, like vanilla JavaScript, makes me find each element and change it step by step.

3. What is a component, and why is React component-based?

A component is a function that takes props and returns JSX. The UI becomes a tree of small pieces, and that gives four benefits: reusability, isolation, composability and testability.

4. What is Vite, and why use it?

Vite is a dev server and build tool. It serves native ES modules, so it starts almost instantly and hot-reloads, with no bundling in development. npm run build makes the optimized production bundle. Setup is npm create vite@latest, choose React and JavaScript, npm install, then npm run dev. Around it sit ESLint, Prettier, React DevTools and VS Code.

5. What is JSX?

JSX is HTML-like syntax inside JavaScript, but it is not HTML. Babel compiles each tag into a React.createElement() call that returns a plain object. The rules are: one root element or a fragment, curly braces for JavaScript expressions, camelCase attributes like className and onClick, and every tag closed, like <br />. Lists need a key so React can track items.

6. How does a React app get onto the screen?

index.html has one empty <div id="root">. main.jsx calls createRoot(document.getElementById('root')).render(<App />). React builds a Virtual DOM tree from <App />, creates the real DOM nodes once, and from then on owns everything inside #root. Without that div there is nowhere to mount.

7. What is a functional component, and what is its render cycle?

A functional component is just a function that returns JSX. React mounts it, renders it, and commits the result to the DOM. Whenever its state or props change, it renders again and the cycle repeats.

8. What is the Virtual DOM, and what is reconciliation?

The Virtual DOM is a lightweight in-memory copy of the UI, made of plain JavaScript objects. On each update React builds a new tree, diffs it against the old one, and patches only what changed in the real DOM. That diff-and-patch process is reconciliation. It avoids costly full re-renders, because real DOM updates are the slow part.

9. Explain immutability, shallow vs deep copy, and referential equality.

React checks whether state changed by comparing references, not contents. So I never mutate; I make a new array or object, like setItems([...items, x]). Spread makes a shallow copy: a new top level, but nested objects are still shared. structuredClone makes a deep copy, fully independent. If I mutate an array and set the same array back, the reference is unchanged, so React skips the re-render.

10. What are props, and how do they enable reuse?

Props are inputs a parent passes to a child. They are read-only, so data flows one way, and I destructure them, like function Avatar({ src, alt }). One component gives many looks, like a Button with variant="danger". children is composition: whatever I nest inside <Card>...</Card> arrives as {children}. State is different: it belongs to the component and changes through useState.

11. What is conditional rendering?

Showing different UI depending on a condition. There are four ways: && to show something or nothing, a ternary for either/or, an early return for cases like loading, and an element variable for complex logic. I can't put if inside JSX because braces only accept expressions.

12. What is lifting state up?

When two components need the same changing data, I move the state to their closest common parent. Data goes down as props, and changes come back up through callback props, so there is one source of truth. In my practice code, App holds selectedStudent, StudentList calls onSelectStudent, and StudentDetails displays it.

13. What is the difference between container and presentational components?

One job per component. A container, the "smart" one, owns state and logic and passes data and handlers down, with little styling. A presentational component, the "dumb" one, gets everything through props and only renders markup and styles, so it is easy to reuse and test.

14. What is Tailwind, what does utility-first mean, and how do breakpoints work?

Tailwind gives me small utility classes, like px-4, bg-blue-600 and rounded-lg, that I compose in the markup instead of writing CSS files. There is no naming, styles sit beside the markup, and it uses one consistent scale. The downside is long class strings, so I extract repeated patterns into components or variant maps. It is mobile-first: no prefix applies to all screens, and sm: 640, md: 768, lg: 1024, xl: 1280 and 2xl: 1536 apply from that width up.

15. What are accessibility and semantic HTML?

Accessibility means everyone can use the page. I use semantic elements: button for actions, nav, header, main and footer for structure, and label paired with input. I keep everything keyboard-reachable, keep enough colour contrast, add alt text, keep visible focus styles, and use ARIA only when plain HTML isn't enough.

JavaScript quick hitsMust know

16. var vs let vs const?

var isn't block-scoped and can be updated and redeclared. let is block-scoped and can be updated but not redeclared. const is block-scoped and can be neither reassigned nor redeclared, though an object or array inside it can still be changed. In React I use const by default.

17. What is an arrow function?

A compact function: (a, b) => a * b. With no braces it returns implicitly. It has no this, arguments or super of its own, and it can't be used with new.

18. map, filter and reduce?

map returns a new array with every item transformed. filter returns a new array with only the items that pass a test. reduce boils the array down to one value. None of them change the original. map is how React turns data into a list of elements.

19. Spread vs rest?

Same ..., opposite jobs. Spread expands an array or object into pieces, like [...arr, 4] or { ...user, age: 21 }. Rest collects leftover values into an array, like function sum(...nums) or const [first, ...others] = arr.

20. What is destructuring?

Unpacking values from arrays or properties from objects into variables in one line, like const { name } = user. In React it is how components read props: function Card({ name }).

21. How do ES modules work?

Each file is its own module. export shares things and import pulls them in. A file has one default export, imported without braces, and any number of named exports, imported with braces.

22. In StudentList, why key={student.id}?

Each item in a mapped list needs a stable, unique key so React can match items between renders and update, move or remove the right one. An id is better than the array index, because indexes shift when the list changes.

32. What is SEO, and why do SPAs need extra work for it?

SEO is optimizing a site so search engines can find and rank it. An SPA's first HTML is a nearly empty shell that JavaScript fills in, so it needs extra work, such as server-side rendering or static generation and good metadata.

33. What are metadata and meta tags? Is <title> a meta tag?

Metadata is information about a page, such as its description, author and viewport settings. Meta tags are <meta> elements in the <head>, like <meta name="description" ...>, <meta charset="UTF-8"> and <meta name="viewport" ...>. <title> is not a meta tag; it is its own element.

34. What is MVC, and where does React fit?

Model-View-Controller splits an app into the Model (data and business logic), the View (the UI) and the Controller (handles input and updates the model and view). React is mainly the View layer.

35. What are the disadvantages of React?
  • The ecosystem changes fast, so it is hard to keep up.
  • It has a learning curve: JSX, state and the Virtual DOM.
  • It is unopinionated, so project structure can be inconsistent.
  • Documentation and official resources can feel limited.
  • It only covers the view layer, so you add libraries for routing and state.
  • JSX can be a barrier at first.
36. What is a bundler?

A tool that combines many JavaScript, CSS and asset files into a few optimized files, so the browser makes fewer requests and downloads less. Webpack, Parcel and Rollup are bundlers. Vite uses native ES modules in development and bundles for production.

37. What is a diffing algorithm?

A method for comparing two versions of a data structure to find what differs. React uses one to compare the old and new Virtual DOM trees, so it can update only the parts that changed.

38. Is React a library or a framework?

React is a library focused on building the UI, the view layer. It doesn't include routing or app-wide state management, so you add those yourself.
